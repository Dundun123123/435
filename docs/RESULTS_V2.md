# 优化版实测结果（v2）

数据：同一份20 Newsgroups，18,311篇、3,663,692词、94,287个不同词。每种配置重复5次，报告中位数；batch-size=500。

## 优化内容

1. 工作进程保留词频，不再把词频回传主进程后又发回。
2. 每个工作进程只接收一次全局IDF，不再每批重复传输。
3. 按文章批次字符数估计工作量，贪心分配，按原索引恢复顺序。
4. 复用输出词对象，减少pickle重复序列化。
5. 关键词模式在工作进程选择top-k，只回传所需关键词；串行执行相同选择工作。

## 正式重复实验

完整向量和关键词提取是两种输出任务，分别比较，不能交叉比较。计时都包括进程启动、输入分配、计算、通信、结果合并和关闭；不包含文件读写。

## 结论与限制

本次全量数据、4进程配置在两种任务下均比串行快，但收益有限。不能据此推断所有数据规模或所有进程数都更快。小数据启动成本占主导；8进程在本次测试中更慢。1000篇/每批500篇仅2批任务，配置4或8进程实际只启动2进程，效率表按配置进程数计算。

未放慢串行、未复制数据扩大负载、未删掉并行通信计时。不同电脑、后台负载、解释器与缓存状态会影响结果，请按README复测。

正确性：results/optimized_verification.txt 核对scikit-learn及边界输入；results/full_corpus_verification_v2.json 核对全部文档的完整向量及两种模式top-10与完整向量截断结果。可运行 validate_delivery.py 重做全量验证。

results/benchmark、INITIAL_RESULTS.md和full_corpus_verification.json是初版历史结果；results/optimization_probe是开发期3次重复的探索结果，都不与本表混合。results/seq_v2.jsonl 与 par_v2.jsonl 是新版本演示输出，单次运行时间不替代中位数。
